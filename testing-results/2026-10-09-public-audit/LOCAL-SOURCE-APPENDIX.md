# Separate source assessment — account-based checkout

**This is not a list of confirmed defects on the current public femioapp.com.** Local HEAD `0ee7dff` from 6 October 2026 describes a Supabase-backed account application. The live public site instead advertises an upcoming on-device mobile product. Matching deployed-source identity was not established.

The three subagents inspected the local implementation against persona jobs and current competitor capabilities. These observations preserve work that may matter if this application remains relevant. No account, invitation, consent, medication or health record was changed. No fixes were made. Pure-function edge cases reported by the cycle subagent are identified below; they were not authenticated browser tests and were not independently re-executed by the parent.

P1 means a high-impact concern requiring targeted verification; it does not prove exposure, injury or a legal violation. Conditional v2 issues only matter when that surface is enabled. Database constraints, current production flags and any other clients were not exhaustively assessed.

## Strengths to retain if this product continues

The reviewed source separates education from diagnosis, implements immediate self-harm help before screener submission, places contact-care guidance before movement counting, preserves pregnancy rows when ending, starts sharing categories off, excludes screeners/crisis data from sharing, omits intimate notes/doses from partner payloads, and treats unknown age conservatively for analytics/research. These are source strengths, not production certification.

## Verification before acting on this appendix

Establish which build, backend and flags use this code. Then run the corresponding synthetic scenario and observe the actual resolved persona and rendered surface. Test empty and populated records, history correction, prior loss followed by live birth, stale dating, multiple pregnancies, treatment episodes, no-period context, cross-tab/offline faults, sharing races/revocation and actual deletion. Run RTL, both themes and real assistive technology. Do not turn unresolved source risks into claims about the public website.
