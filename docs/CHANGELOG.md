# Changelog
All notable changes to Femio V2.

## [Unreleased]
### Fixed
- Critical client-side hydration crash (all signed-in pages): `env.ts` validated the whole `process.env`, which Next.js leaves empty in the client bundle, so validation threw and `/welcome`, `/track`, `/dashboard`, and `/settings` crashed on hydration in production (SSR/curl couldn't detect it). Now references each `NEXT_PUBLIC_*` var explicitly. Caught by the new Playwright e2e harness and verified fixed on live prod.

### Added
- Passwordless sign-in for returning users (P1.12.1, → apps/web/src/app/[locale]/sign-in/, app/api/auth/callback/): a returning user (or a staff member who needs the translation portal) can sign back in with a secure emailed magic link — no password, matching how email accounts are created at onboarding. A callback route establishes the session and returns you to the dashboard, with clear "check your email" and error states and links between sign-in and account creation. Full i18n.
- Translation portal + DB-backed UI strings (P1.19, ADR-014, → apps/web/src/lib/i18n/, components/admin/translation-editor.tsx, app/[locale]/(app)/admin/translations/): a staff-only portal (admin/translator) to review and approve interface strings per language, with a per-locale status board, filter, and one-click Save & approve that publishes the string immediately. Under the hood the local JSON catalogs stay the base and only **human-approved** rows from the database are overlaid on top, so nothing changes until a string is deliberately approved — an empty or unavailable table simply leaves the app on JSON (no regression). A seed script imports the JSON catalogs into the database (English pre-approved as master; Arabic/French/Spanish as drafts awaiting review). Activation needs a one-time staff-role grant + running the seed with a service key. Machine-draft prefill (DeepL) and live preview are tracked as a follow-up.
- Doctor-visit summary / PDF export (P1.16.1, → apps/web/src/lib/account/visit-summary.ts, app/[locale]/(app)/summary/): a printable `/summary` page (linked from Settings) presents a curated, human-readable snapshot — cycle count/average/range and recent periods, recent symptoms with intensity, medications, self-reported flagged topics, and key dates — for sharing with a clinician. PDF is produced by the browser's own print / Save-as-PDF, so health data never leaves your device or session (no PDF library, no server rendering); app chrome is hidden when printing. It carries a clear "personal tracking summary, not a medical record or clinical advice" disclaimer. Built on a pure, unit-tested summary builder. Full i18n.
- Per-symptom severity + custom symptoms (P1.14.1, → apps/web/src/lib/cycle/symptoms.ts, components/cycle/log-symptoms.tsx): symptom logging now records an intensity **per symptom** rather than one shared value, and lets people **add their own** symptoms (normalized + de-duplicated, stored on the open symptom type and shown as typed). The curated list grew from 16 to 26 (mood swings, low motivation, joint pain, constipation, diarrhoea, hot flushes, spotting, brain fog, higher/lower sex drive) in all four locales. The full 100+ taxonomy stays a translation-portal (CMS) task. Backed by pure helpers with unit tests and an end-to-end check.
- Fertile window + ovulation on the tracker calendar (P1.13.2, → apps/web/src/components/cycle/cycle-calendar.tsx): the month calendar now overlays the estimated fertile window (soft teal band) and ovulation day (highlighted), derived from the last period and average cycle, with a legend, screen-reader labels, and a clear conception-awareness-only note (never framed as contraception). The predicted-period band stays amber so the phases read as distinct.
- Cycle calendar + flow intensity (P1.13.1, → apps/web/src/lib/cycle/calendar.ts, components/cycle/cycle-calendar.tsx): the tracker now shows a real month calendar — an accessible table with previous/next navigation and locale-aware month/weekday labels — where logged period days are marked (with a dot whose shade reflects flow, and the flow named in each cell's screen-reader label so it never depends on colour alone), the predicted next-period window shows as a soft band, and today is ringed. Logging a period now offers a flow choice (spotting/light/medium/heavy) saved with the entry. Arabic weeks start on Saturday; RTL verified. Built on a pure, tested month-grid helper.
- Role-based access control foundation (P1.18, → docs/18_RBAC_MODEL.md, apps/web/src/lib/auth/): the web app gained role-awareness on top of the existing DB + CMS role model — `STAFF_ROLES`, pure `hasRole`/`isStaff` predicates, `getMyRoles()` (RLS-scoped, empty for consumers), and a `requireStaff()` Server-Component guard ready for the admin-portal pages (P1.19–P1.21). The RLS audit now also proves **no privilege escalation** (a non-admin cannot grant itself a role or read another user's roles). The five-role model (admin/editor/medical_reviewer/translator/support) and where each layer enforces it is documented; `support` is intentionally app-side only (no Payload CMS access).
- Security review + automated RLS audit (P1.23, → docs/compliance/SECURITY_REVIEW.md, scripts/security/rls-audit.mjs): `pnpm rls-audit` proves the data-layer guarantees against the live project using only the publishable key — the consent gate (health writes blocked pre-consent, allowed after), owner-only isolation (a second user cannot read/update/delete another's rows), the unauthenticated anon role reading no health data, and the GDPR delete cascade (10/10 pass). A SECURITY_REVIEW doc maps Femio's posture to the OWASP Top-10 (2021), documents the rate-limiting/abuse posture, and lists the remaining launch-gate items (independent pen-test, at-rest-encryption confirmation, `pnpm audit` in CI, CSP/headers, staff MFA, breach alerting).
- Accessibility audit in CI + DB-free e2e (P1.22 / P1.5.2, → apps/web/e2e/a11y.spec.ts, ci.yml): a Playwright + axe-core WCAG 2.1 A/AA scan (serious+critical gate) over home, calculators, help-now, welcome and the open crisis dialog — in both an LTR and an RTL locale — plus the crisis and home e2e now run in CI on every PR (built app served via `next start`). Live-Supabase flows are tagged `@live` and remain a local gate (`test:e2e:ci` runs `--grep-invert @live`). The audit found and fixed two genuine AA contrast failures (see Changed).

### Changed
- Fixed two WCAG AA contrast failures surfaced by the new axe audit (→ assets/brand/tokens/): accent text on `accent-soft` was 3.80:1 — added an `--accent-soft-text` token (raspberry-700, 5.11:1) and pointed the accent badge + home chip at it; `--text-subtle` was 4.45:1 on the off-white page background — darkened neutral-550 (#787189→#726C82, now 4.81:1). Tokens re-verified programmatically.

- Global crisis-safety routing (P1.26, → apps/web/src/components/crisis/, apps/web/src/lib/crisis/, ADR-013): a persistent "Need help now?" launcher (mounted in the locale layout, so on public + onboarding + calculator + signed-in pages) opens an accessible native `<dialog>` — focus-trap, Escape, RTL — showing the **medically-reviewed, verbatim** crisis wording (contact local emergency services **or** go to the nearest emergency department; guidance for someone worried about another person). A public, account-less `/{locale}/help-now` page mirrors it (server-rendered, `noindex`, excluded from the sitemap). The interface **collects and transmits nothing**: `useCrisisHelp().open()` takes no reason/score/country/health-data payload and there is **no analytics** anywhere on it (opening it could reveal mental-health intent); copy is static/bundled so it opens instantly and **offline**. English is the only human-approved locale — Arabic/French/Spanish render the English fallback tagged `lang="en" dir="ltr"` until a human linguistic reviewer signs off. A CI guard (`crisis-lint`) fails on expired copy (EN due 2027-07-23), missing approved-locale review metadata, or translation-key mismatches. The single outbound directory link (Find A Helpline) is optional and env-gated (`NEXT_PUBLIC_CRISIS_DIRECTORY_URL`), locked by build-failing validation to the canonical `https://findahelpline.com` host with no query/fragment and opened with `referrerPolicy="no-referrer"`; unset → the link is hidden and the emergency fallback still works. Verified: 5 unit + 10 Playwright e2e (4 locales unauthed, keyboard/focus-trap/Escape, RTL EN-fallback, offline, no unvetted link, noindex) all green, and a non-canonical directory host proven to fail the build. DPO + medical sign-off on the global-only posture remains a launch gate (DPIA §5).
- Offline-capable logging (P1.17, → apps/web/src/lib/offline/): period + symptom logs made while offline are queued in IndexedDB and synced to Supabase when connectivity returns (flush on mount + the browser 'online' event). Real (non-network) errors surface immediately instead of being queued. Verified end-to-end in a headless browser with offline emulation.
- Playwright e2e harness (partial P1.22, → apps/web/e2e/, playwright.config.ts): headless-Chromium end-to-end tests — home + Arabic-RTL smoke and a full onboarding → anonymous sign-in → dashboard flow against live Supabase. Enables offline testing (P1.17) and RTL snapshots.
- GDPR data export + delete-account (P1.16, → apps/web/src/app/[locale]/settings/, supabase/migrations/0003): a privacy/data settings page that downloads the user's full owner-scoped record as JSON and permanently deletes the account. A `delete_account()` RPC removes the auth user and cascades all health data; the client falls back to deleting the profile row (also cascades) if the RPC isn't deployed. Verified live that deletion erases all health data. PDF export tracked as a follow-up.
- Dashboard + insights v1 (P1.15, → apps/web/src/app/[locale]/dashboard/): a mode-adapted overview (current cycle day, next-period window, average length, top logged symptoms, and the TTC fertile window) driven by the user's persona_state and logged data. Pure, tested insight helpers. Onboarding now lands on the dashboard.
- Symptom & mood logging (P1.14, → apps/web/src/components/cycle/log-symptoms.tsx): a curated mood/body/other taxonomy with multi-select chips, optional intensity, and a note, saved to `symptom_logs` (owner-scoped + consent-gated), with recently-logged symptoms shown on the tracker. Full i18n. Extensible to the full 100+ taxonomy (P1.14.1).
- Cycle tracking (P1.13, → apps/web/src/lib/cycle/, /[locale]/track): an auth-gated tracker to log period starts (owner-scoped + consent-gated) with history, and **uncertainty-honest predictions v1** — a variability model over the user's own history that shows the next period as a soft dashed *window* + confidence, never a single certain date, and degrades gracefully (wider window, no "late" counter) in irregular mode. 8 table-driven tests. Onboarding now lands on the tracker. Full i18n.
- Onboarding (P1.12, → apps/web/src/components/onboarding/): a privacy-first welcome wizard at `/[locale]/welcome` — choose a life-stage focus (cycle / TTC / pregnancy / menopause), pick anonymous (default) or an email account, and grant granular consent (core required + optional insights/research).
