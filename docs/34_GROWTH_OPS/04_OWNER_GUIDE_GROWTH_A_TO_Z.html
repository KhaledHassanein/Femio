04 — Growing femio after launch, A to Z: every step you do by hand

For Khaled. This continues docs/33_REBUILD_V3/06_LAUNCH_GUIDE_A_TO_Z.md (accounts, the closed test, production). That guide gets the app into Play; this one sets up everything that measures, earns and feeds the site afterwards. Same rules: plain words, in order, each step says how long, what to click, what to paste and what "done" looks like. When a step says a session, open Claude Code in the repo and paste the quoted line. Nothing here needs you to write code.

One decision first, before parts C–E and H: ADR-075 in docs/DECISIONS.md. It changes one sentence of rule 4 so the website may measure visits and carry ads, after consent and without anything a woman typed. The app stays untouched. Say "accept ADR-075", "accept without ads", or "decline" to a session. If you decline, do parts A, B, F, G only.

The shape of it. A → repository safety (10 min). B → Search Console (15 min, no decision needed). C → Google Analytics 4 (20 min). D → Google Tag Manager + the consent banner (40 min, the most careful part). E → Meta Business + Pixel (30 min). F → Canva and the social accounts (1 hour over a few days). G → the agent routines (20 min + 45 min a week forever). H → AdSense (20 min to apply, then waiting). I → Play payments profile and the premium product (30 min, in February). J → ASO upkeep (monthly, 15 min). The interactive checklist (https://claude.ai/artifact/V3exHDJpZasUkRoWuameDp, private to you) mirrors every step; tick there as you go.

Where things live. Keep a single page in your password manager called "femio growth" with every id this guide produces (Search Console property, GA4 Measurement ID G-…, GTM container GTM-…, Meta Pixel ID, AdSense publisher id pub-…). Never paste an id into chat; a session only ever needs the public ones (G-, GTM-, pub-), and you put those into Vercel yourself (part D step 8 shows how).

A · Repository safety (10 min, once)

Why: from now on agents open pull requests every week. main must accept nothing without you.

  1. github.com → your femio repository → Settings → Branches → Add branch ruleset (or "Add rule" on older UI). Name: main. Target: main.
  2. Tick Require a pull request before merging, approvals 1. Tick Require status checks to pass: search and add the Vercel check (Vercel) and, if the gate runs in Actions, gate. Tick Block force pushes. Save.
  3. Settings → Actions → General → Workflow permissions: Read repository contents, and tick Allow GitHub Actions to create and approve pull requests (routines open PRs).
  4. Done when: a session says "push to main" and GitHub refuses with "protected branch"; the session then opens a PR instead and you press Merge.

B · Google Search Console (15 min, no decision needed)

Why: it is the only place that shows which Google searches show femio, free, no cookie, no banner. Routine R1 reads it every Monday.

  1. search.google.com/search-console → Add property → choose Domain → type femioapp.com → Continue.
  2. Google shows a TXT record. Open vercel.com → your team → Domains → femioapp.com → DNS Records → Add: Type TXT, Name @ (leave blank if Vercel says so), Value = the string Google showed → Save. Back in Search Console press Verify (DNS can take up to an hour; press Verify again later if it fails).
  3. In Search Console → Sitemaps → paste https://femioapp.com/sitemap.xml → Submit.
  4. Settings (gear) → Users and permissions → add the Google account you use with the Ahrefs connector as Full if it is different from the one you used here (R1 reads through it).
  5. Done when: Sitemaps shows "Success" with a page count; after 2–3 days Performance shows impressions. Tick B in the checklist and write the property name on your "femio growth" page.

Alternative if DNS is awkward: URL-prefix property https://femioapp.com → HTML tag method → copy only the content="…" value → Vercel → Project femio-web → Settings → Environment Variables → NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION = that value → Redeploy (Deployments → ⋯ → Redeploy). The site already prints the tag when the variable exists.

C · Google Analytics 4 (20 min; after "accept ADR-075")

  1. analytics.google.com → Admin (gear, bottom left) → Create → Account. Name KM Digital Labs. Data-sharing boxes: untick all except "Technical support". Next.
  2. Property: name femio website, time zone (GMT+02:00) Cairo, currency US Dollar. Next. Business details: industry Health, size Small. Objectives: tick Examine user behavior only. Create. Accept the terms (Egypt as country). Also open the "Data Processing Terms" and accept them (needed for EEA visitors).
  3. Data stream: Web → URL https://femioapp.com, stream name femioapp.com → Enhanced measurement: leave ON but open the gear and untick "Form interactions" and "Site search" (the site has neither; fewer surprises). Create stream.
  4. Copy the Measurement ID (G-XXXXXXXXXX) to your "femio growth" page. Do not install the tag Google offers; GTM will carry it (part D).
  5. Admin → Data settings → Data collection: turn OFF "Google signals" (no cross-device profiles; this is a health site). Data retention: 14 months. Data collection → Granular location and device data: untick EEA countries' city precision if offered.
  6. Admin → Data filters: the "Internal traffic" filter → set to Active and in Data streams → Configure tag settings → Define internal traffic add your home IP so your own visits are excluded.
  7. Admin → Property access management → add the account used by routines as Viewer (same account as B step 4).
  8. Done when: Admin → Data streams shows the stream with the G- id; nothing else yet (no data until part D is live). Tick C.

D · Google Tag Manager and the consent banner (40 min; the careful part)

Why: one GTM script in the site carries every tag after it, and a certified banner makes every tag wait for consent. The site code for this is built by a session (01_ANALYTICS_AND_PIXELS.md §6); your part is the container and the banner.

  1. tagmanager.google.com → Create account: name KM Digital Labs, country Egypt. Container: name femioapp.com, platform Web → Create → accept terms. Copy the container id GTM-XXXXXXX from the top bar to your "femio growth" page. Close the install dialog (the session installs it).
  2. Left menu Admin → Container settings → tick Enable consent overview. Save.
  3. Tags → New → name GA4 · configuration → Tag type Google Tag → Tag ID = your G-… → Triggering: "Initialization – All Pages" → Save.
  4. Open the tag again → Advanced settings → Consent settings → "Require additional consent for tag to fire": add analytics_storage. Save. (This is the line that makes GA4 wait.)
  5. Variables → Configure → tick everything under Clicks and Pages. Then User-defined variables → New → Data Layer Variable for each: page_type, article_slug, calculator_slug, placement, from_locale, to_locale, source_host, country (the site pushes these; names must match exactly).
  6. Triggers → New → Custom Event for each event in 01_ANALYTICS_AND_PIXELS.md §4 (article_read, calculator_open, calculator_used, get_app_click, help_now_open, language_switch, outbound_source_click). Then Tags → New → Google Analytics: GA4 Event for each, event name = the same, parameters = only the ones listed in that table, consent setting = analytics_storage, trigger = its custom event. Seven tags. (A session can hand you a GTM container export JSON with all of this ready; Admin → Import Container → Merge saves the typing. Ask: "export the GTM container JSON for ADR-075".)
  7. The consent banner. Two routes; use the first:
    • AdSense "Privacy & messaging" (free, Google-certified, needs the AdSense account from part H even before ads are approved): adsense.google.com → Privacy & messaging → GDPR → Create message → sites: femioapp.com → languages: English, Arabic, French, Spanish → Consent options: tick "Do not consent" (so decline is one tap) → Styling: match Dusk Bloom (plum #8A3572 button, cream #FBF7F3 background) → Publish. Also create the US state regulations message (opt-out) and publish. The message tag is served through the AdSense script, which the session adds to the site when NEXT_PUBLIC_ADSENSE_CLIENT is set. Verify in step 9 that it also updates Consent Mode for the GA4 tag; if it does not, use the second route.
    • A free certified CMP (CookieYes, Cookiebot or similar, check the free tier's page limit against about 160 pages): sign up → add femioapp.com → enable Google Consent Mode v2 and IAB TCF v2.3 → languages EN/AR/FR/ES → copy the script → give the session the snippet URL, never a key: "mount this CMP snippet before GTM".
  8. Put the ids in Vercel yourself: vercel.com → project femio-web → Settings → Environment Variables → Add NEXT_PUBLIC_GTM_ID = GTM-… (Production, Preview) → Save → Deployments → latest → ⋯ → Redeploy. Then tell a session: "GTM id is set in Vercel; verify consent on the preview".
  9. Verify (10 min, do it yourself once so you understand it). In GTM press Preview → enter https://femioapp.com/ar → Connect. A new tab opens with a "Tag Assistant connected" badge. In the Tag Assistant window: the Consent tab shows every type Denied on load; no tag listed under "Tags fired" except nothing (the GA4 tag must sit under "Tags not fired"). Press Allow on the banner → the Consent tab flips analytics_storage: Granted → the GA4 configuration tag appears under "Tags fired". Open a calculator and tap a day → calculator_open then calculator_used events appear with only calculator_slug. If any tag fires before Allow, stop and tell a session exactly which tag.
  10. GTM → Submit → version name v1 consent + GA4 → Publish. In GA4 → Reports → Realtime: your visit appears within a minute (unless your IP is filtered).
  11. Done when: step 9 behaves as written and Realtime shows a visit from another device. Tick D.

E · Meta Business Suite and the Pixel (30 min; after "accept ADR-075")

Why: a pixel on the site builds an audience of visitors for organic reach later and shows which Facebook/Instagram posts bring readers. Expect Meta to restrict a health domain to "Core Setup"; the plan already assumes it.

  1. business.facebook.com → Create a business portfolio: name KM Digital Labs, your name, your business email. Confirm the email.
  2. Settings → Business assets → Pages: add or create the femio Facebook Page (name femio, category Health & wellness website, bio from 04_GROWTH_PACK.md §1, Arabic first). Connect the Instagram account from part F when it exists.
  3. Settings → Data sources → Datasets (older UI: Pixels) → Add → name femioapp.com → Set up manually → copy the Dataset/Pixel ID (digits) to your "femio growth" page. Do not install the code; GTM carries it.
  4. Events Manager → the dataset → Settings: Automatic advanced matching: OFF. Track events automatically without code: OFF (we fire exactly three). Under Data sharing restrictions read what Meta applied; if it says Core Setup, nothing changes.
  5. Business Settings → Brand safety and suitability → Domains → Add femioapp.com → verify by DNS TXT (Vercel → Domains → DNS Records, like part B step 2) or by the meta tag (give the content value to a session: "set Meta domain verification tag").
  6. In GTM (part D): Tags → New → Facebook Pixel template (search the Community Template Gallery: "Facebook Pixel" by facebookarchive/Meta, or the official "Meta Pixel" template) → Pixel ID = yours → Event: PageView → trigger All Pages → Consent settings: require ad_storage and ad_user_data. Two more Pixel tags: ViewContent on triggers article_read and calculator_open; Lead on get_app_click. No parameters. Preview as in D9: nothing fires before Allow; after it, PageView appears in Events Manager → Test events within a minute. Submit and publish v2 meta pixel.
  7. Done when: Events Manager → Overview shows PageView from femioapp.com with "Browser" as the source. Tick E.

G · The agent routines (20 min once, then about 45 min a week)

  1. In Claude Code (desktop app) say: "create the growth routines from docs/34_GROWTH_OPS/ routines".   3. Once a week, drop the Play Console export into the repo for R7: Play Console → Statistics → Export report (installs, retention) → save the CSV as docs/34_GROWTH_OPS/reports/play/YYYY-WW.csv (git-ignored; only summaries are committed). H · Google AdSense (20 min to apply; then days to weeks of waiting; after "accept ADR-075")

Apply when the site has steady readers (the plan's threshold: about 1,000 sessions a week or eight weeks after launch, whichever comes first).

  1. adsense.google.com → Get started → your site femioapp.com → country Egypt → accept terms. Google shows a code snippet with your publisher id pub-…: write the id on your "femio growth" page; do not paste the snippet anywhere.
  2. Payments → Payments info: name and address exactly as on your bank account and ID. Payment method: add it when AdSense asks (Egypt: wire transfer to your bank; the account name must match; AdSense also sends a PIN by post to your address before the first payment, so the postal address must be real).
  3. Tell a session: "AdSense client id is pub-…, mount the verification script". It sets NEXT_PUBLIC_ADSENSE_CLIENT in Vercel through you (same as D8) and the site serves the AdSense script on article pages, which also carries the Privacy & messaging banner (D7). Back in AdSense press Verify. Then wait for the review email (days to weeks).
  4. When approved: Ads → By site → turn Auto ads OFF (we place units ourselves) → Ads → By ad unit → Display ads → create article-mid, article-end, hub-top (responsive) → copy only the slot numbers (digits) → tell a session "AdSense slots: mid …, end …, hub …". It places the three units per 02_MONETIZATION.md §1.1.
  5. Brand safety → Content → Blocking controls → Sensitive categories: block Dating, Drugs & supplements, Get rich quick, Politics, Religion, Sexual & reproductive health, Birth control, Cosmetic procedures, Astrology & esoteric, Weight loss, Significant skin exposure. Also Ad serving → "Ad load" slider to Low.
  6. Done when: an article shows two labelled ads below the fold, Lighthouse performance on it stays ≥ 85 (the session runs it), and AdSense → Reports shows impressions. Tick H.
