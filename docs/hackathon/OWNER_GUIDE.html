1 · What you are finishing

femio's assistant is built and tested; what is left is connecting your own Firebase project, proving it on a phone, and submitting.

femio is a private women's-health app: her records stay on her phone. The hackathon entry shows hybrid AI (some work on the phone, some in the cloud) using Firebase AI Logic (Google's toolkit that lets an app call Gemini models, on the phone or in the cloud, from one piece of code). Inside the app, a bundled registry of 89 trusted sources (passages from CDC, MedlinePlus, Office on Women's Health, NICHD, NIDDK and NCI, plus links to WHO, NHS, ACOG, RCOG and NICE) answers her questions offline, numbers each source, and says "Not covered yet" when it has nothing. Gemini Nano (Google's small AI model that runs on supported phones) writes a cited summary on the phone. The Cloud boost is an optional switch, off by default, used only when her phone has no Nano. Safety rules (danger signs, heavy bleeding, birth-control questions) always run before any model and always win.

3 · Register the app and SHA fingerprint

Tell Firebase which app is allowed to call it: the package name com.femioapp.femio and its SHA-256 fingerprint.

A SHA-256 fingerprint is a long code made from the key that signs an app. It is how Google recognises "this is really your app". It is not a secret, but it is long, so copy it with the mouse.

1Register the Android app

Do
Add an Android app with the package name below. Skip the step that offers google-services.json; femio does not use that file.
Where
Firebase console → Project settings (gear icon) → Your apps → Add app → Android. Package name: com.femioapp.femio. Give it any nickname. Click through, skipping the download.
You should see
Under Your apps, an Android app named after you with the package com.femioapp.femio, and an "App ID" field.
If it fails
If it says the package is already used, you probably registered it before in another project; open that project instead, or use the one you already have.

2Get the debug SHA-256

Do
Ask the build tool to print the fingerprints.
Where
In PowerShell: 
cd E:\Femio\.claude\worktrees\firebase-hackathon-eligibility-833c52\apps\mobile\android
.\gradlew signingReport
In Git Bash use ./gradlew signingReport. (Use the folder where your working copy of the repo lives; the path above is the normal one.)
You should see
A long printout. Find the block headed Variant: debug and the line starting SHA-256: (colon-separated pairs of letters and digits).
If it fails
Run flutter doctor in apps/mobile; Java and the Android tools must show a tick. If it still stops, run flutter clean, then flutter pub get, and try again.

3Add the fingerprint in Firebase

Do
Paste the SHA-256 value into the app's fingerprint list.
Where
Project settings → Your apps → your Android app → Add fingerprint → paste → Save.
You should see
The fingerprint listed under the app with type SHA-256.
If it fails
A fingerprint with the wrong format is rejected; copy only the value after SHA-256:. Later, the Play Console app signing key adds a second fingerprint; that is for the Play release, not the demo (see the App Check Play Integrity page: firebase.google.com/docs/app-check/android/play-integrity-provider).

6 · App Check: debug token first, then enforcement

Add the debug token to Firebase first; only after that switch enforcement on, never the other way round.

App Check is Firebase's guard that answers "is this request really from my app?" before it lets the call use your quota. Enforcement means Firebase refuses calls that fail that check. A debug token is a one-off code a test build prints so Firebase will trust it. If you switch enforcement on before adding the token, your own test calls are refused (403 errors).

1Make the app print its token

Do
Start a log stream on your computer, then on the phone open Settings → Assistant (that starts Firebase and App Check), or Today → Ask femio and ask any question. 
adb logcat
logcat is the phone's running diary. Leave it running while you use the app.
You should see
Many lines scroll past. Stop it with Ctrl+C after you have used Ask.
If it fails
No lines at all: re-check adb devices (section 5).

2Find the token line

Do
Filter the diary for the App Check line. 
adb logcat -d | findstr /i /c:"debug secret"
(Git Bash: adb logcat -d | grep -i "debug secret". -d prints what is stored, then stops.)
You should see
A line from App Check that tells you to enter a debug secret in the Firebase console, followed by a long code (letters, digits, dashes). That code is the token. Treat it like a password: use it only in the next step.
If it fails
No such line: open Ask femio again, ask another question, and repeat. Exact wording can differ by version; the official page is firebase.google.com/docs/app-check/android/debug-provider. If you still cannot find it, tell a Claude session "no token line in logcat" without pasting the log.

3Add the token in Firebase

Do
Firebase console → App Check → Apps → your Android app → the three-dot menu → Manage debug tokens → Add debug token → paste → Save. Also make sure the Play Integrity provider is set up for the app (look for "Play Integrity" on the same page; docs link in section 3).
You should see
Your token listed under Manage debug tokens.
If it fails
If you cannot see "Manage debug tokens", look for the app row's menu or settings icon; the console moves things. The official page above shows the current layout.

4Turn enforcement on, then re-test

Do
In App Check, open the list of products (APIs) and switch enforcement on for Firebase AI Logic (look for it by that name, or by "Gemini Developer API"). Then use Ask femio again with Cloud boost on (section 8).
You should see
The product shows "Enforced", and the app still answers.
If it fails
If the app now shows errors or 403, switch enforcement back off, check the token was saved, use the app once more and try again. See section 15.

9 · Remote Config

Remote Config is not built in this version; there is nothing to set up.

Remote Config is a Firebase feature that changes an app's settings from the console without a new release. femio does not use it in this version. Do not enable it, and do not mention it in the Devpost form as a feature.
