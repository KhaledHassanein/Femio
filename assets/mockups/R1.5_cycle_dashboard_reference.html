R1.5 — the cycle dashboard, designed as modules

The daily screen for the largest group (docs/25 §3.3), drawn the way R1.6 drew pregnancy: a module inventory first, then assembled personas, because R2 makes the dashboard an ordered list the engine chooses and a fixed composition would be undone by the first persona that reorders it.

One honesty note, and it is the difference between this file and R1.6. R1.6's assembled screens were copied from buildExperienceConfig's real output. Track B has no registry rows yet — registry/ holds A, D and E — so the module lists below are read from the persona specs (B1 §E/§I, B2/B3/B4/B5/B6 §I) and are a specification for Track B, not a copy of it. When R2.8 encodes those rows they must match this file; if they do not, one of the two is a bug, and docs/25 §1 says the reference is the bug report. Everything the running app already renders — the hero, the band, the persona offer, the quick-log row — is drawn as it actually behaves today.

1 · The module inventory

Each module drawn alone. If one cannot survive being dropped into a different position, the module boundary is wrong — and that is much cheaper to learn here than in React.

2 · Assembled — five women, one engine

B1 and B5 differ in what the hero is allowed to say. B2 and B4 differ in what the hero is — a control and a count, not a prediction. None of this is an if in a screen.

3 · The hardest states

First run, where the product currently looks least finished — and Arabic dark, where the band, the phase strip and the flow strip all have to mirror.

What this decides

1 · The honest absence gets the hero, at the same size as the confident answer

B5/B6's hero is the same slot, the same gradient and the same type scale as B1's — and it says Femio will not guess. The band is still drawn, dotted and unfilled, because demoting "we don't know" to a small grey line below a card teaches that uncertainty is a failure state. It is not: for a woman with 90-day gaps it is the true answer, and product rule 3 makes it the only one Femio is allowed to give. There is no "late" counter in any state in this file, and no state in which one could appear.

2 · Different personas get a different hero, not the same hero with more cards

This is the test R1.6 could not run, because every pregnancy persona shares the D1 spine. Here B2's hero is a control — today's mood and symptoms, logged from the hero itself, because B2 §I puts the daily log first and her question is not "when" — and B4's hero is a count, her own bleeding record and its trend. If the engine can only reorder cards under a fixed hero, it is a sorting function, not an experience engine.

3 · The quantifier counts; it does not grade the period

B4 §I asks for a "plain-language band" on the bleeding score. This reference does not draw one, for the reason P2.4 gave when the MRS shipped: "you used 14 products over four days" is arithmetic on her own answers, and "your period is heavy" is a clinical assessment. It is the third time the product has made this call (ADR-049's missing result, R1.6's verdict-free clinical strip, the MRS's missing severity word), and the answer does not change with the instrument.

4 · The ring is replaced, not simply removed

docs/25 §5a rejects rings because they imply a target and a completion. Removing one and leaving text is how the current dashboard ended up flat. What replaces it is the phase strip — proportional segments with today marked — and it carries two rules: the ovulatory segment fades at both edges, because its timing is inferred and a crisp block would claim a measurement, and the word "fertile" and any date appear nowhere on it, because B1 is non-TTC by default and a fertile window she did not ask for is the pregnancy-funnel default her spec is written against (B1 §A).

5 · Her range is shown over the typical range, and nothing grades the difference

The personal-normal module draws her shortest–longest against the 21–35 day typical range with the source named. No in/out marker, no colour change, no tick — the same rule as the lab reference range in R1.6. ACOG's vital-sign framing is the reason the context is there at all; deciding what her position in it means is the clinician's.

6 · Change awareness is never a danger colour

B1 §D is explicit that a pattern change raises content prominence and never a red banner. So the module uses --primary-soft, sits mid-screen rather than above the fold, and its action is reading rather than routing. The cycle dashboard has no red panel at all — which is the opposite of the pregnancy dashboard, where warning signs sit high because late is the harmful direction. Two life stages, two answers, one design language.

7 · "Explore other chapters" is a module, because a rule with no UI is a claim

Product rule 2 says personalize, never restrict, and every B spec repeats hidden-but-reachable in its §I. Today that is true of the router and invisible on the screen. Drawing it as a real, low-emphasis module is what makes the promise checkable — and it is where TTC, pregnancy, contraception education and perimenopause live for a woman who was never asked about them.

8 · First run is a designed state

A new account has no cycles, so the hero has nothing to predict. The empty state is a botanical mark, one Fraunces sentence and one action — not a card with a fallback string in it. docs/25 §4 names this exactly: she sees the app at its emptiest first, and that is currently when it looks least finished.

Known gaps

  • Track B has no registry. Filed as R2.8; until then these lists are a specification, and the box at the top of this file says so rather than implying an engine output that does not exist.
  • The pattern/correlation module is drawn thin. The real one is R4 (P2.5) and drawing it properly would be designing a feature that has no engine behind it.
  • Not composited in a browser here. The template was executed in node — module coverage counted, no undefined leaking — but the visual judgement is the owner's, as with R1.3, R1.4 and R1.6.
  • Copy is a draft and the Arabic follows the pattern of the approved cycle-mode strings rather than being newly reviewed.
