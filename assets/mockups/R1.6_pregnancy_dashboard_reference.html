R1.6 — pregnancy dashboard, designed as modules

Not a screen. docs/25 §5: R2 turns the dashboard into an ordered list of modules chosen by the engine, so a pixel-perfect fixed composition would be undone by the first persona that reorders it. Each module is drawn alone below, then assembled into four real personas. The assembled screens are driven by the module lists buildExperienceConfig actually emits — copied from its output, not imagined — so the reference and the engine cannot disagree.

1 · The module inventory

Each one has to survive being dropped into a different position. If it doesn't, the module boundary is wrong — and that is much cheaper to learn here than in React.

2 · Assembled — the same engine, four different women

D1 and D3 differ by one strip. D3 and D7 differ by which strip. D7 + prior loss keeps the clinical hero and changes the tone. None of this is an if in a screen.

3 · The hardest state

D7 in Arabic, dark — RTL with a clinical strip and Latin lab units in it.

What this decides

1 · A strip is a row of facts, never a verdict

Every clinical strip shows the value, the unit and the lab's own reference range, and nothing else. There is no pass/fail badge, no colour-coded "in range", no arrow saying good or bad — because deciding that is diagnosis (product rule 1), and D7 §G says it explicitly: "Lab values are shown with your lab's reference range for your records — this is not a diagnosis." The sparkline shows her own trend; it makes no claim about where it should be.

2 · The hero is the pregnancy, even when a condition is what she is worried about

docs/09 §8 works the flagship through: pregnancy + thyroid + prior loss → hero is the pregnancy timeline, with thyroid and PAL as strips. That is what the D7 + D2 screen shows. The milestone card is present and subordinate — the engine demotes it rather than deleting it, and this reference had to match that after the code was fixed to stop an emotional layer stealing the hero.

3 · The term band never fills toward the due date

It draws 37–42 weeks with today marked inside it (ADR-053). A bar filling toward the EDD makes one date look like a finish line, which is the single-certain-date framing product rule 3 exists to prevent.

4 · Warning signs sit high, not at the bottom

In pregnancy, late is the harmful direction. The module is a red-flag panel above the fold in every assembled screen, and it carries no phone number — the global-only crisis posture (P1.26.1) applies here too.

5 · Strips sit directly under the hero

The engine originally appended them, which put every clinical strip below the quick-log row — where you put something nobody asked for. D7 §I asks for "the D1 week-by-week hero plus a thyroid strip". Building this reference is what exposed it; the fix and its test landed with R2.2.

Known gaps

  • Not composited in a browser here. The template was executed in node — state counts, no undefined — but the visual judgement is the owner's, as with R1.3 and R1.4.
  • No botanical line-work. A clinical dashboard is not where docs/25 §5a puts illustration; it belongs in empty states and onboarding.
  • Copy is a draft and the Arabic needs P1.29's reviewer, though the pattern follows the strings already approved for pregnancy mode.
  • D4 is not drawn. It reuses D3's glucose strip plus device and lab modules that are variants of ones here; drawing it would add no decision.
